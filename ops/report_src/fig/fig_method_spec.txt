METHOD (Planner–Speaker user simulator for multi-turn conversational data search; Task 2 = free-running session)

The simulator plays a real user (a researcher looking for a dataset) talking to a search assistant (the task agent). Each user turn works as follows.

1. Inputs. A scenario gives the user's persona and goal (topic, context, datasets they already know).
2. Planner. A Planner LLM (Qwen3-4B-Instruct) reads the goal, the conversation so far and the accumulated profile notes, and writes a JSON plan with these fields: critique (what its previous plan got wrong), act_distribution (dialogue moves, each with a probability and a target length in words), goal_met (yes / partly / no), still_wanted, end_session (true if this is the user's last message), profile_note (how this person writes).
3. Implicit profile. The profile_note of every turn is appended to a growing list of notes about how this person writes. The notes feed back into the Planner at the next turn and are also given to the Speaker.
4. Few-shot pool. For every candidate, 3 real messages of other users with the same writing style are drawn from the training conversations (never the current goal or persona).
5. Speaker. A frozen Speaker LLM (Ditto-8B) turns the plan, the notes and the examples into 4 candidate user messages.
6. Guards and selector. Candidates that copy an example or break format are removed; a Borda selector ranks the rest by closeness to the planned length and by style similarity (SimCSE) and picks one message.
7. The chosen message goes to the task agent (gpt-oss-120b), whose reply is appended to the conversation history, which the Planner reads at the next turn (a loop).
8. Ending. If end_session is true, the chosen message is a closing message and the session ends after it; the session also ends if the chosen message is blank, or at 10 user messages.
